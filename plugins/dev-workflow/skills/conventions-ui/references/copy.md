# Copy

## Short labels

One word, or as few as possible. The screen around a label already says a lot, so the label doesn't repeat it.

| Instead of | Write |
|---|---|
| Save your changes | Save |
| Enter the customer's email address | Email |
| Click here to add a new invoice | Add invoice |

An explanation goes in a tooltip only when a person would otherwise get it wrong. Most labels need none.

## Never say it twice

Each piece of text adds only what isn't visible already, and no two places say the same thing:

- A tooltip doesn't restate its label. On "Due date", "The date this is due" adds nothing. "Counted from the invoice date" does.
- A hint under a field doesn't repeat its placeholder, and a placeholder isn't a label.
- A page title, its heading and the menu item that opens it don't each explain the page.
- An empty state says what to do next, once.
- An error says what went wrong and how to fix it, next to the field it's about, and not again in a banner.

## Optional fields

Mark them quietly, the one way the design system does it, such as a muted marker beside the label. Never "(optional)" in the label. When most fields are optional, mark the required ones instead.

## Before delivering

Reread every string on the screen, in place. Cut each word that doesn't change what a person understands or does. Check that two places don't say the same thing, and that the same thing has the same name everywhere, as the glossary names it.
